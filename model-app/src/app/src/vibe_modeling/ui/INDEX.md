# Frontend index

React + Vite app under `src/app/src/vibe_modeling/ui/`. TanStack Router (file-based), shadcn/ui, Orval-generated API client, Tailwind v4. One line per file/dir; keep current-state only when adding/moving/removing.

## Routes (TanStack file-based)

- `routes/__root.tsx` — Top-level layout (ThemeProvider, Outlet, AppToaster, `ErrorDetailsHost`, `FeedbackDraftPageScope`).
- `routes/_sidebar/route.tsx` — Authenticated `_sidebar` layout shell + navigation.
- `routes/_sidebar/index.tsx` — Home page: workflow orientation strip, "Jump back in" (businesses, industries and visited model versions by per-user visit recency), pruning stale visit rows on load, "Start something new" entry points.
- `routes/_sidebar/profile.tsx` — Profile view: identity, display name and emails from `/current-user`.
- `routes/_sidebar/settings.tsx` - Settings: five URL-backed tabs (`?tab=`): **agent** (one agent status line `components/settings/agent-status-row.tsx` above the form, the readiness banner except for the "no notebook" reason, notebook path with the pin sentence as a tooltip, runtime concurrency/statistics, and the Settings run time budget in hours with bounds from the API; the form is `noValidate`, so Save shows the app's inline errors, each tied to its number input with `aria-describedby`), **platform** (metamodel-catalog card wired to get/setMetamodelCatalog with inline `^[a-z][a-z0-9_]+$` validation + SQL warehouse + the "Optional features" section `components/settings/optional-features.tsx`), **sources** (`GithubConfigSection` repo owner/name + auth mode + UC connection name, plus the anonymous-mode rate-limit banner driven by `getSourceCapabilities.auth_mode`), **sectors** (CRUD), **preferences** (per-user diagram column-mode defaults + reset-to-defaults). `validateSearch` redirects legacy deep-links `diagram`->`preferences`, `warehouse`->`platform`, `github`->`sources`, `assessment`->`platform`.
- (The source explorer is no longer a standalone route. It is hosted in `components/source-explorer/source-explorer-dialog.tsx`, launched from the Industries page "Download from source" button.)
- `routes/_sidebar/businesses.{index, new, tsx}.tsx` — Business list (with `OobBanner` above the table) + creation.
- `routes/_sidebar/businesses.$businessId.{tsx, index, edit, explorer, runs}.tsx` — Per-business shell (renders `KickstartProgressBanner` and `OobBanner` stacked in one container above the child route), redirect, edit (incl. the proposed Business domains `TagInput` + Organization divisions select - a stored non-preset shows as "Current: <value>" - sent patch-style only when changed, and for app admins a Deployment section with `OrphanSchemasPanel`), model explorer (with friendly 404), runs list. The explorer header carries a "Kickstart a business" action (gated on `kind === "industry"`, opens `KickstartDialog`) and a "Kickstarted from <industry> v<n>" provenance line for kickstarted businesses (`source_industry_id`).
- `routes/_sidebar/businesses.$businessId.runs.{new, $runId}.tsx` — New Run form (validate's blockers, warnings and `prepare` issues, the last as a neutral note; dispatches exactly the server-persisted `selected_for_run` set; shows a read-only scrollable compiled-instructions preview of that set + the per-run instructions editor + an "Edit inputs →" back-link to Compose; Business Domains + Organization Divisions pre-fill from the business's stored `business_domains`/`org_divisions` only for New Base Model on a business without versions). It launches New Base Model, Vibe Modeling and Vibe ECM + MVM only; `operationType` matches an operation name or intent slug in any case, with hyphen, underscore and space equivalent (non-string values are dropped), and a deep link naming install, uninstall or generate-samples opens the default operation with a notice (links to the named version's page, else each scope's latest; Generate Samples "retired"). Advanced Options offer the agent's own values from `lib/run-options.ts` (date and timestamp as Selects); seed `business_domains` show and are sent only for New Base Model and Vibe ECM + MVM. Advanced Options also carry "Run time budget (hours)", prefilled from the Settings default (`getAgentConfig`) and always sent as `runtime_budget_hours` on validate and create; out of the API's bounds it shows an inline error tied to the input with `aria-describedby` (repeated next to Start Run when the panel is closed), disables Start Run and skips the validate request; without a loaded agent config the field is absent and nothing is sent. Model Size shows the base version's scope (an empty scope counts as ECM, like the backend) and is locked on every vibe iteration (the backend dispatches the parent's scope); until the user picks Organization Divisions, a vibe iteration's divisions follow that size (derived, not stored). When `getAgentCompat` reports an installed agent older than 5.3.3 (an unparseable version counts as unknown), the form locks All domains + Full Run (`fullRunOnly`) with a "Full Run only" note linking to Settings (both groups are `aria-describedby` that note). For a vibe iteration it carries the `VibeScopeControl` (scope, domains, run type). Until the user picks a run type it is Dry Run for either scope (the form default only; the API default `RunIn.dry_run=false` is unchanged); a picked one, or a `runMode` deep link, sticks. A scoped run sends `vibe_scope` / `vibe_scope_domains` / `dry_run` on validate and create, an unscoped Dry Run sends only `dry_run: true`, and an unscoped Full Run sends none of them (body unchanged from before the scope feature); a scoped run previews the server compile (`compileVibeInputs` with `vibe_scope_domains`), lists the excluded items with reasons, hides and does not send `business_domains`, and blocks submit when nothing is in scope. Deep link: `?operationType=vibe-iterate&sourceVersion=N&sourceScope=ecm|mvm&scopeDomains=a[,b]&runMode=dry|full` (`scopeDomains` starts the scope on Some domains). With `scopeFrom=feedback` (set by the compose surface) the scope came from the selected feedback: a banner names the source until the scope is edited, a note under the scope control says how many selected items are model-wide and not sent in a scoped run (read from the scoped preview), and a base that is not the scope head opens on All domains with "Scoped runs need the latest version (vN).". On All domains a "Scope to a, b" hint (from one unscoped compile, `input_scope_domains`; nothing is fetched for a base behind the scope head) offers the selection's domains when they are some but not all of the base's. The catalog starts as `installTargetCatalog` of the latest version. A vibe's Advanced Options start from `getRunDefaults` for the base (`lib/run-defaults.ts`): untouched fields follow the base, an edit to an unlocked field stands across a base change, the fields the agent keeps are disabled (readable: full opacity on the muted surface) and `aria-describedby` one note, an off-list base value shows as its own item, an unreadable base file locks them with no value, a failed read shows a note and the form's values; Start Run waits while the defaults load ("Reading the base model's conventions", also a submit guard); validate and create send the same Advanced Options; a vibe sends every known convention field, blanks included, and Vibe ECM + MVM sends Schema Prefix as `ecm_schema_prefix` once the base's conventions loaded (after a failed read it keeps the form's ECM prefix); Organization Divisions take the producing run's value when it recorded one. Run-detail page with cancel dialog and Dry Run / Scope badges read from `parameters_json`.
- `routes/_sidebar/businesses.$businessId.assessments.tsx` — layout `<Outlet/>` for the assessment routes inside `FeatureGate feature="assessment"` (the not-installed page when the skill isn't installed).
- `routes/_sidebar/businesses.$businessId.assessments.index.tsx` — Assessments list page: batches table (created, `v{version} {scope}`, domain count, roll-up `StatusBadge`, creator, Relaunch for batches with a failed run) linking to the batch page, plus a "New assessment" link to the wizard; while not ready the results stay readable, New assessment and Relaunch are hidden and `FeatureNotReady` shows.
- `routes/_sidebar/businesses.$businessId.assessments.new.tsx` — New assessment page; validates `?versionId=&domainId=` search params and renders `AssessmentWizard` in an `AssessBoundary` behind `FeatureGate feature="assessment" requireReady` (the not-set-up notice until ready).
- `routes/_sidebar/businesses.$businessId.assessments.$batchId.tsx` — assessment batch page; renders `BatchStatus` in an `AssessBoundary`.
- `routes/_sidebar/businesses.$businessId.model.$version.$scope.{tsx, index, $domainName.*}.tsx` — Model version pages: overview, per-domain, per-product. Each of the three has a friendly not-found card that resets when the route params change. The version page's `DeleteVersionButton` labels Delete per state (draft, replaced, head) and disables it with the reason, shown on its own line under the tab bar (`components/model/toolbar-note-slot.tsx`: `useToolbarNoteSlot` is the shell's line, `ToolbarNote` portals into it), for an installed version (with Uninstall, and the newer versions to delete first when there are any) or a superseded one in the middle (`lib/version-lifecycle.deleteState`). The version page and the domain page share the wrapping toolbar pieces in `components/model/toolbar.tsx` (`ToolbarTabsList`, `ToolbarActions`). The domain page offers "Iterate on this domain" (F6, a scoped vibe deep link) on the scope head.
- `routes/_sidebar/businesses.$businessId.model.$version.$scope.inputs.{tsx, index, $inputId}.tsx` — Vibe Inputs compose surface (ComposeSurface) + card-details page (metadata/instruction over the scoped ModelView viz tabs).

## Lib

- `lib/api.ts` — Orval-generated OpenAPI client + hooks (do NOT edit manually; regenerates from backend OpenAPI).
- `lib/notify.ts` - The one place toasts are raised for failures and notes: `notifyError` (persistent error toast with Copy and Details), `notifyConfigMissing` (the `config_missing` renderer), `notifyWarnings(title, warnings)` (one warning toast with the response's `warnings` as its description; false when there are none). Used by the import dialogs and the out-of-band banner for a success that carries warnings.
- `lib/api-error.ts` — `ApiError` discriminator + helpers: `apiErrorMessage` (toast-friendly message extraction), `parse409<T>(err, errorLiteral)` (the shared 409-conflict-envelope parser — unwraps the body or `detail`, checks the `error` discriminator; used by `parseConflict` in import-new-business-dialog, `parseDownloadConflict` and the assessment `parseBlocked`), `parseConfigMissing`, `parseSettingRefused` (400 `model_service_refused` / `setting_refused` → `{error, key, message, status?}`), `parseSettingsError` (every error a Settings change fixes: `config_missing` with its own links, a refusal with its link from `REFUSED_SETTING_LOCATIONS` and `refusedKey`; a feature setting's link always points at its card (`featureSettingsUrl`); read by `notify.notifyConfigMissing` and `SettingsErrorNotice`), `parseNeedsConfirmation` (the run create's 422 `needs_confirmation`: every subject-bound confirm issue, rendered instead of the cut `message`), `parsePlainConflict` (a 409 `{message}` with no `error` key, shown inline with Try again) and `parseAdminHelp` (the assessment `error: "admin_help"` detail at any status → `AdminHelp {message, job_url, run_url, runs_path, job_reader, not_ready}`).
- `lib/selector.ts` — Default query selector (`useSuspenseQuery({ ...selector() })`).
- `lib/hooks.ts` — Shared React hooks (toast, route helpers, `useDebouncedValue`, `useInvalidateOnRunTerminal` - refetch every query when a run that was in flight ends, once per transition and per `scopeKey`). `isBusinessAdmin(role)` is the one app-or-business-admin check (admin gate, cleanups panel, OOB banner, version operation dialog, link-run action).
- `lib/use-now.ts` — `useNow(active, intervalMs = 1000)`: the current time, re-rendering every `intervalMs` while active (run pipeline elapsed times, the taxonomy busy countdown each second; the assessment ingest-retry row every 30 s); no API imports.
- `lib/business-cache.ts` — `invalidateBusinessLists(queryClient)`: invalidates ALL `/api/businesses` list queries (unfiltered + kind-filtered) via a queryKey-prefix predicate, so the kind-filtered Industries list refreshes after download/kickstart/create/edit/delete (the bare `listBusinessesKey()` misses the `{kind}` key).
- `lib/retry-transient.ts` — `retryOnTransientGateway()` / `isTransientGatewayError()`: bounded auto-retry (linear backoff) for POSTs that hit a transient edge-proxy 502/503/504; retries clear-on-retry gateway hiccups (E-04, kickstart) while rethrowing 4xx / app-500 unretried. `onTransientError` fires per occurrence (retried or exhausted) for logging.
- `lib/request-timeout.ts` — `withRequestTimeout(ms, run)`: gives `run` an `AbortSignal` and rejects with `RequestTimeoutError` after `ms` (the race settles the wait even if `run` ignores the signal); used by the compose Start run compile and the installation-drift reconcile.
- `lib/client-telemetry.ts` — `reportClientGatewayError()`: records a browser-observed transient gateway error in BOTH the console and the app logs (fire-and-forget beacon to `POST /api/client-telemetry/gateway-error`), so an E-04-style 502 stays diagnosable in `databricks apps logs` even when a client retry recovers it.
