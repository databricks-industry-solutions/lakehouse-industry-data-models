# clinical_trials v2 - standards crosswalks

CSV crosswalks from `clinical_trials` v2 ECM attributes to the clinical data standards they implement or feed. They are metadata only: the silver model stays business-shaped, and SDTM or OMOP datasets are produced downstream from it.

Generated by `tools/standards_crosswalk/generate_crosswalks.py` from the curated rules in `tools/standards_crosswalk/rules/clinical_trials.csv`.

## Files

| File | Standard | Rows | Target validation |
|---|---|---|---|
| `crosswalk_sdtm.csv` | CDISC SDTMIG 3.4 | 38 | Checked against COSMoS SDTM dataset specializations |
| `crosswalk_cdash.csv` | CDISC CDASHIG 2.x | 4 | Curated (collected variables only, such as AETERM and AESTDAT; coded and derived variables are SDTM-only) |
| `crosswalk_usdm.csv` | CDISC USDM v4 (DDF-RA) | 5 | Checked against the DDF-RA `USDM_API.json` classes and attributes |
| `crosswalk_fhir.csv` | HL7 FHIR R4 | 12 | Curated R4 element paths, not checked against StructureDefinitions |
| `crosswalk_omop.csv` | OHDSI OMOP CDM v5.4 | 2 | Checked against the OHDSI v5.4 field-level CSV |

Columns: `domain, product, attribute, standard, standard_version, target_entity, target_element, match_type (exact|derived|partial|related), confidence (high|medium|low), evidence, source_ref`.

## Coverage

This is a seed set, not a complete crosswalk. The 61 rows cover the safety, subject, laboratory and study-design attributes with the clearest standard counterparts, out of about 16,200 attributes in the v2 ECM. Most attributes are operational (CTMS, finance, supply, workforce) and have no counterpart in these standards. A missing row means there is no rule yet, not that no mapping exists.

In v2, categorical attributes that draw on CDISC Controlled Terminology are foreign keys to `datamanagement.codelist_term` (for example `subject.demographic.sex_codelist_term_id`), so their rows are `derived`: the SDTM value is the term's `submission_value`. v2 also tags 302 attributes with the standard element they implement (rule ATT-RUL-074); reading those tags directly is the next step to raise coverage.

## Regenerate

```bash
python3 tools/standards_crosswalk/generate_crosswalks.py \
  --model data-models/clinical_trials/v2/ecm/model.json
```

Output defaults to `<model version>/standards/`. On first run the generator downloads the pinned spec files listed in `tools/standards_crosswalk/sources.json` (raw GitHub at fixed commit SHAs, about 3.6 MB) into `tools/standards_crosswalk/.cache/`, which is gitignored. Third-party spec files are never committed. Any rule whose target is not in the downloaded spec is dropped and logged.

Tests: `cd tools/standards_crosswalk && python3 -m unittest test_generate_crosswalks`.

## Caveats

- **SDTM validation is conservative.** COSMoS covers the SDTM variables used by published biomedical-concept specializations, not the full SDTMIG. Valid variables outside that set (for example `AESTDY`) are dropped until a full SDTMIG variable list is available. That list needs a CDISC Library API key.
- **No licensed content.** Rows say that an attribute holds a MedDRA, WHODrug or SNOMED CT code. No dictionary terms or codes are included.
- **FHIR paths are not profiled.** Mappings name element paths and do not bind value sets or constrain profiles.
- **Sentinel and PCORnet are not mapped yet.** Neither publishes a machine-readable spec the generator can fetch. Their diagnosis tables hold ICD and SNOMED codes, not MedDRA, so trial safety data links to them through a code-system crosswalk, not a field-to-field mapping. Rows will be added once they can be checked against the published table specs.
