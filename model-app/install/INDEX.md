# install/

First-time (and idempotent re-run) workspace install. See `INSTALL.md` for the operator guide.

Self-contained: files here only reference `install/`, `src/app/` and root config (`databricks.yml`).

- `install.sh` — End-to-end installer: the flags first, needing only `python` (`deploy_settings.py resolve --check`, offline: a bad value or a flag whose feature is turned off on the same run stops before the tool preflight); then it looks the app up (`_install_common.py app-exists`; a failed lookup stops a real run): an existing app's settings are read from the running app (`deploy_settings.py resolve --read-deployed`, shown as `(deployed)`; a flag changes a value), and the installer asks y/N on every run, also when every value is flagged (`--confirm`; `--yes` takes them, no terminal refuses; nothing is deployed on a refusal); a setting that can't be read stops (exit 2 naming its flag; a stopped app says to pass the flags or start it); a new app gets its flags over the defaults (its own project, catalog and database); a Lakebase project or catalog that is new for the app is checked against the other apps on the workspace; nothing left by an earlier run is read or written; `--database` when the Postgres database differs from `--catalog`; `--dry-run` does that lookup, readback and check read-only (no question) and reports "unknown" when the lookup fails; `--disable-taxonomy-builder` / `--disable-assessment` turn a deployed feature off; `--enable-github-publish` deploys the `github-publish` target after checking the `github_pr` connection, and `--disable-github-publish` switches back, both as an update of the same app; `--adopt-existing-app`, `--yes` and `--apply-without-plan-file` pass through to the deploy with `--ignore-env`, and `--adopt-if-ours` when the readback recognised the app (`DEPLOY_SETTINGS_RECOGNIZED`); `--allow-shared-resources` keeps a shared catalog on this run), then the tool preflight with the CLI minimum (`bundle_state.py check-cli`, refused below), the guarded deploy `bundle_state.py deploy` of the resolved target, `apps deploy` from `bundle_state.py source-path` (after waiting, up to 10 minutes, while a pending or active deployment is in progress, as after `apps start` on a stopped app) until the app is RUNNING, Lakebase provisioning (`--lakebase-min-cu` / `--lakebase-max-cu`, `--lakebase-resize`), catalog grants, the optional model-service check (`--enable-taxonomy-builder [--taxonomy-model-service <catalog.schema.service>]`), the optional assessment (`--enable-assessment [--assess-reader-sp <application_id>]`, with a warn-only reader check), `--no-run-tags` (exports `VIBE_MODELING_RUN_TAGS_DEFAULT=false`, the seed of Settings -> Agent -> "Annotate jobs with run tags"; default on), app start + deploy, the warn-only app tagging step `[tag]` (`tag_app.py`), warn-only verification.
- `in_flight_guard.sh` — Refuses a (re-)deploy while the existing App reports in-flight runs on `/api/health` (exit 2, no override; the message says to wait for the run or cancel it on its run page); passes without asking when there is no App yet (existence and the URL from `_install_common.py app-exists`); when it can't tell (app list or health unreadable, no URL, no token, no python or `jq`) it warns with the reason and asks y/N on a terminal, refuses with no terminal, and proceeds without asking with `ASSUME_YES=1` (the callers' `--yes`); runs in flight always refuse. Also used by the other deploy scripts.
- `bundle_state.py` — The bundle's deployment state per app and the guarded deploy, used by `install.sh`: `bundle_root` (`~/.bundle/vibe-modeling/<app>`, `databricks.yml`'s `workspace.root_path`), `source_code_path`, `state_app_names` (the apps a state acts on: a direct-engine `resources.json` entry by `__id__`, with `StateMismatch` naming both when `__id__` and `state.name` differ, which refuses in the root check and for this app's own legacy root, and skips another app's legacy root; a Terraform state by `name`, since its `id` is the app's service principal client id; only `resources.json` and the Terraform state are read, never a `.backup`; unknown formats are None), `check_cli` (`MIN_CLI` 1.20.0, refused below), and `deploy`: deletes the local cache `.databricks/bundle/<target>/` first (the plan always comes from the remote state), refuses a root whose state manages another app, copies the state of an earlier per-target root (`dev`, `github-publish`) that manages this app when the root has none (never overwrites, leaves the old root; both roots managing it refuse, naming both; not when the app runs from its own root, whose state was deleted), binds an existing app with no state anywhere after the plan check with `--adopt-if-ours` (the caller recognised it: `_install_common.is_our_app`) when the deploying identity created it, asks on a terminal when another did (`--yes` does not answer; otherwise `--adopt-existing-app`), refuses any other existing app with no state naming its creator and description unless `--adopt-existing-app`, asks y/N (`--yes`; no terminal refuses) before a legacy copy or adoption of an app another identity created (`confirm_foreign_app`), then `bundle plan -o json` to `install/.generated/plans/<app>.json`, refuses any delete, recreate or id change (or an unknown action, or no app entry) and removes the state this run copied, binds an adopted app only after that check and checks again (anything that stops the run after the bind, interrupts included, unbinds and removes the state the bind wrote; a failed undo names the reason and the manual recovery), counts an empty root state (no resources at all: what an unbind leaves) as none and refuses one with resources but no app, and applies exactly that plan with `bundle deploy --plan` (`--apply-without-plan-file`, or `VIBE_MODELING_APPLY_WITHOUT_PLAN_FILE=1` unless `--ignore-env`: a plain deploy after the same check). App existence from `_install_common.find_app`; remote state through the SDK. Exit 2 refused, 1 failed.
- `build_and_render.sh` — Bundle artifacts hook (`--bundle-hook`, passed on to the render, with `--app-name ${var.app_name} --target ${bundle.target} --profile "${workspace.profile}"` from `databricks.yml`, passed to the resolver as the deployed app and target), also run by `install.sh` before `bundle deploy`: resolves the settings with `deploy_settings.py resolve` from the exported values only (no workspace call, no file of an earlier run; refuses, exit 2, before any build, without an app name or unless every rendered value and the target are exported, pointing at `install.sh --dry-run`), `apx build` (wrapped in `frontend_lock_guard.py`), then renders `src/app/.build/app.yml` from them and, from the same assessment flag, `install/.generated/app_scopes.yml` (the `databricks.yml` include for the App's `user_api_scopes`; gitignored).
- `deploy_settings.py` — The deploy settings of every deploy path: `resolve` merges a flag (`--set`), the environment (unless `--ignore-env`; a value replacing a different deployed one is noted), the running app (`--read-deployed`: `read_deployed` reads the nine rendered values from the `app.yml` of the active deployment's snapshot through `_install_common.read_active_app_yml`, with the deployment's `env_vars` on top (one with only `value_from` is unread), the source folder only for a deployment without a snapshot; the target from the `github_pr` resource; the Lakebase range from the deployed project's `primary` endpoint, a range that can't be read or that `check_capacity` refuses keeps the default with a note, a flagged other project drops it; at most three CLI calls of 120 s; `PREDATES` (run tags 0.9.0, taxonomy and assessment 0.8.0) takes the default with a note; a stopped app's reason says to pass the flags or start it; `recognized` through `_install_common.is_our_app`) and the defaults; nothing from a file of an earlier run, `src/app/app.yml` or `.build/app.yml`; prints each value's source (`flag`, `env`, `deployed`, `default`, `bundle`), validates (booleans, target, Lakebase capacity via `check_capacity`, reader UUID, the model-service name through `backend/taxonomy/service_name.py`, a flag whose feature is off), fails closed without an app name and when any of `REQUIRED` (the rendered values and the target; the model service and reader only while their feature is on) is neither flagged, exported nor read (`UNREAD_INSTALL` with `--install-flags` names install.sh's flags, `UNREAD_ENV` the variables; the hook's `NOT_EXPORTED`); `--fresh-ok` or `VIBE_MODELING_ALLOW_DEFAULT_SETTINGS=1` (where the environment is read) allow defaults; `--database-follows-catalog` keeps a deployed database that differs from its catalog; `--confirm` asks y/N every time (`--yes`; no terminal refuses); `--check` validates the flags offline (`check_flags`); `shared_resource_check` (with `--read-deployed` or `--fresh-ok`, not `--no-guard`, never in the hook) checks only a project or catalog value that differs from the app's own deployed one (or whose own value was unread): candidates are the other apps of `our_apps`; a project another app's service principal has a role on refuses (`SHARED_PROJECT`, no flag lifts it), as does a project whose roles can't be read or need more than 20 role lookups; a catalog another app's running app.yml sets, or that its service principal holds privileges on or owns (`<catalog>._metamodel` first, else the catalog), refuses (`SHARED_CATALOG`) unless `VIBE_MODELING_ALLOW_SHARED_RESOURCES` is set on this run; apps that neither signal can see are named in a warning (not for a catalog that does not exist yet); a refusal also carries the note that the app's own value could not be read; the app list has the lookup's 300 s, then 60 s per call, 180 s in all, at most 25 snapshots; notes a bundle target switch; refuses with the hook's `--bundle-target` a target other than the exported one (`TARGET_MISMATCH`) and with `--bundle-app-name` an exported app name other than the deployed one (`APP_NAME_MISMATCH`); `--shell` prints `export` lines and `DEPLOY_SETTINGS_RECOGNIZED`. Stdlib only (the hook may run without the SDK).
- `_feature_defaults.sh` — The install-time default of every deploy setting and the app name, as literal `DEFAULT_<NAME>="<value>"` lines (the project, database and catalog are the default app's; other apps derive theirs from the name): sourced by `install.sh` (its `--help`), parsed by `deploy_settings.py`.
- `frontend_lock_guard.py` — Runs a build command in `src/app`; when it changed the meaning of `package.json` (dependency specs, overrides) or `bun.lock` (workspace specs, overrides, per-package `name@version` + integrity; header, formatting and tarball URLs ignored), restores both files and exits 1 with a diff and fix steps for installers and maintainers. Catches apx's per-build `bun add --dev` moving the frontend devDependencies off the `overrides` pins in `package.json`.
- `render_app_yaml.py` — Line-oriented rewrite of the known `app.yml` env values (`ENV_TARGETS`), incl. `VIBE_MODELING_TAXONOMY_BUILDER_ENABLED` / `VIBE_MODELING_TAXONOMY_MODEL_SERVICE`, `VIBE_MODELING_ASSESSMENT_ENABLED` / `VIBE_MODELING_ASSESS_READER_SP` and `VIBE_MODELING_RUN_TAGS_DEFAULT` (`--run-tags true|false`, default `true`); every value is written as an escaped YAML double-quoted scalar; `render_bundle_scopes` + `--bundle-scopes-out` write the App's `user_api_scopes` fragment: a per-target override (`BUNDLE_TARGETS`, kept equal to `databricks.yml`'s targets by a test) with `workspace.workspace` when the assessment is on, deleted when it is off (never an empty list; a re-run with the assessment off drops the scope); with `--bundle-hook` (the `databricks.yml` build hook) a changed fragment, incl. absent vs present, exits 3 with "re-run the deploy", since the bundle already loaded the old one. `read_env(text)` is the inverse of `render`: the value each `ENV_TARGETS` entry of an `app.yml` sets (double-quoted as JSON, single-quoted, or bare; a trailing comment dropped; `valueFrom`, no value or no entry is absent; other entries are never read).
- `_install_common.py` — `find_app(name, profile)`: the one "does this App exist" check (from `databricks apps list --output json`'s exit code and membership, never error text; `AppLookupError` otherwise), also a CLI, `python install/_install_common.py app-exists <name> [--profile <p>]` (exit 0 and the app's JSON when it exists, 3 absent, 1 unknown; `list_apps` raises on a failed CLI, empty output, or anything but a complete app list), `uses-github-connection` (an app's JSON on stdin: exit 0 when it declares the `github_pr` resource), used by `install.sh`, `in_flight_guard.sh`, and `fix_industry_prefixes.py`. Helpers shared by the `install/*.py` scripts (imported as `_install_common`; `install/` is `sys.path[0]` when they run as `python install/<script>.py`; imports without the SDK, then `workspace_client` raises `RuntimeError`): `load_backend_module(path)` loads a dependency-light app backend module by file path (the operator env has no `vibe_modeling`; cached per path; `RuntimeError` when the file is missing or not loadable), `workspace_client(profile, **cfg)` builds the `WorkspaceClient` for a CLI profile, or the SDK default auth when the profile is empty, through an SDK `Config` (so `cfg` takes any `Config` attribute, incl. `http_timeout_seconds` / `retry_timeout_seconds`, which the `WorkspaceClient` constructor rejects; a key that is not a `Config` attribute raises `TypeError`). Used by `check_model_service.py`, `deploy_settings.py`, `grant_catalog.py`, `provision_lakebase.py` and `tag_app.py`; new scripts use it instead of inline copies. `run_cli(args, profile, run, timeout, error)` is the one `databricks` CLI subprocess call (a timeout, the exit code, the last 300 characters of the output, empty output; raises `CliError`, or the class passed, e.g. `AppLookupError` for `list_apps`), with `run_cli_json` and the thin wrappers `get_app`, `export_workspace_file` (`workspace export <path> --format SOURCE`) and `get_lakebase_endpoint`; `lakebase_project_name` / `lakebase_branch_name` / `lakebase_endpoint_name` build the Lakebase resource names (`provision_lakebase.py` uses them); `confirm(question, assume_yes=, no_terminal=, declined=)` asks y/N on stderr, takes `--yes`, raises `NotConfirmed` with no terminal, on anything but yes, at end of input or on Ctrl-C (`bundle_state.confirm_foreign_app` uses it). Workspace reads for the shared-resource check: `list_lakebase_projects`, `list_lakebase_roles` (a service principal's role carries its application id in `status.postgres_role`), `get_lakebase_role`, `get_grants`, `get_schema`, `list_catalogs` (a list answer must be complete). "Ours": `APP_DESCRIPTION` (kept equal to `databricks.yml` by a test), `our_apps(apps)` (the apps with that description, the only candidates of every check) and `is_our_app(app, app_yml_env)` (that description and a running app.yml that sets the Lakebase project, database and catalog). `read_active_app_yml(active, ..., snapshot_only=)` reads the app.yml of an active deployment: its snapshot when it has one (an unreadable snapshot names its creator or an admin, the source folder is never read then), else its source folder, never with `snapshot_only`.
- `provision_lakebase.py` — Lakebase project, endpoint, database and role grants for the app SP; a new project autoscales between `--min-cu` and `--max-cu` (defaults and validation from `deploy_settings.py`); for an existing one `reconcile_capacity` prints the `primary` endpoint's range and changes it only with `--resize`. Resource names from `_install_common.lakebase_*_name`.
- `grant_catalog.py` — Best-effort UC catalog/schema grants + `_metamodel` schema/volume creation for the app SP (loads `backend/services/metamodel_setup.py` by file path); the `_metamodel` grant includes `CREATE_VOLUME` and `MANAGE` on every install (the assessment runs volume and the reader's USE SCHEMA). `catalog_grant_sql` / `schema_grant_sql` render the equivalent GRANT statements (the fallback advice).
- `check_model_service.py` — Read-only check that the app SP can use a UC model service (exists; EXECUTE / USE CATALOG / USE SCHEMA via effective permissions, ALL_PRIVILEGES or ownership); stops with `databricks grants update` commands on a missing privilege, warns when it can't verify; never grants (the three-part name rule, `backend/taxonomy/service_name.py`, is loaded by file path; `install.sh` validates the name up front through `deploy_settings.py`). `--principal <reader>` (default: `--app-sp`) checks the assessment reader instead, WARN-ONLY (exit 0): also warns when the reader does not exist, and prints a reminder (no check) that the app SP needs the Service Principal User role on it.
- `tag_app.py` — Warn-only, idempotent tagging of the Databricks App with the app identity tags (`managed_by`, `dbx_vibe_modelling_app`, `dbx_vibe_modelling_app_version`), the same keys and values as its jobs (`app_identity_tags` from `backend/core/_job_tags.py`, loaded by file path; the version from the built `_version.py`, else `pyproject.toml`): lists the app's tags, creates the missing ones, updates the ones that differ (`update_mask=tag_value`), re-reads a tag whose create failed; every failure warns (CAN MANAGE on the app, ASSIGN on a governed tag) and it exits 0, 2 only on a usage error; the SDK tags module and `tomllib` are imported after the guard, so an old SDK gets a warning. Run by `install.sh`, after `apps deploy`.
- `fix_industry_prefixes.py` — After upgrading from 0.8.x: gives industries downloaded before 0.9.0 the scope prefixes a download adds now, through the app's `POST /api/industries/<id>/scope-prefixes` (`applyIndustryScopePrefixes`; the caller must be an app Admin). `--profile`, `--app-name`, `--industry <name|id>` or `--all`, `--apply` (default: a dry run that changes nothing). Token from `databricks auth token --profile`, app URL from `_install_common.find_app`. Prints one row per version (`changed`, `unchanged`, `skipped`, `failed` with the reason); the app renames nothing in Unity Catalog, rewrites its own model-file copies and registry rows, and skips installed versions. Exit 0 done, 2 a version skipped, 1 an error or a failed version, 3 usage. Stdlib only.
