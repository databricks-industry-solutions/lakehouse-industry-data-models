# Backend index

FastAPI app under `src/app/src/vibe_modeling/backend/`. One line per file/dir; keep current-state only when adding/moving/removing.

## Entry + routing

- `app.py` — FastAPI entrypoint: `create_app(routers=ROUTERS)`; re-exports `ROUTERS`.
- `_routers.py` — `ROUTERS`, the app's router list (legacy `router` with explorer and diagram routes, then every `routes/*` router), and `iter_api_routes` / `iter_route_methods` (route walk across FastAPI 0.135 flat and 0.143 nested routes). Side-effect free, so tests and route-dump tooling mount the same routers without building the app.
- `router.py` — Primary run routes (POST /runs, validate, cancel, /runs/:id, /operations/:id, /agent-config, /progress, /health); at launch composes selected VibeInputs into the dispatched instructions via `compile_inputs` (scoped + unscoped markdown paths separate), returns `agent_markdown` to agent and filters by scope. Its validate and create handlers call the one pre-flight entry point, `services/orchestrator/preflight.run_preflight`; the create branches start the pre-flight's DAG and run its level 3 right before their Run row. One run per business: create reads `_get_or_create_agent_config` first, the pre-flight takes `core._runs.lock_business_for_run` between levels 1 and 2, and no branch commits before its Run row (a commit releases the lock; `tests/test_app/test_drift_concurrent_runs.py` spies on it); retry takes the same lock and active-run check (409) before it re-dispatches. Generate Samples and Revert are retired: a new run of either is refused as an unrecognized intent (422 from `RunIn`), and retry and resume of an old row answer 422. Run delete removes the run's instruction files on the Volume, best effort. Included-only input links: only `compile_inputs.included_input_ids` are linked and consumed, and both launch paths record them in `parameters_json` for retry; excluded (out-of-scope, deprecated) stay open.
- `routes/businesses.py` — Business CRUD + import; create/update carry the proposed `business_domains` + `org_divisions` (patch-style on update). Create flushes the business, adds the seed context and commits once; an `IntegrityError` at the flush rolls back and re-runs the name check: a conflict is the `business_name_taken` 409, any other integrity failure re-raises. Delete goes through `_version_lifecycle.delete_business` and answers `BusinessDeleteOut`. `executeImport` takes an optional `databricks_run_id` and links it after the import commits (`run_link.link_after_import`: a refused link keeps the import, adds a warning and leaves `linked_run_id` null), and an optional `scope` (the user's ECM / MVM choice; a scope the file does not settle and no choice is a 400 that writes nothing). Before it numbers the version, the import takes the business lock (`core._runs.lock_business_for_write`: 409 `run_active` while a run is active, `business_busy` while another request holds it; nothing written) and holds it to the version's commit. The import copies the file's folder into the app's folder for the version through `services/dialog_import`, the model.json with the scope prefix unless agent output. `analyzeImport` reports `inferred_scope`, `agent_output` and the prefixes.
- `routes/run_changes.py` — Run change review, hidden behind `AppConfig.run_change_review_enabled` (off by default, no install flag): every route on `router` answers 404 while it is off (`require_run_change_review_enabled`, built by `core/_features.require_installed`); `config_router` holds the ungated `getRunChangeReviewConfig` (`GET /config/run-change-review`, any role, `RunChangeReviewConfigOut {enabled}`) the UI reads. `getRunChanges` (`GET /businesses/{id}/runs/{run_id}/changes`, any role), `setRunChangeDecisions` (`PUT .../changes/decisions`, ModelerOnly) and `addRejectedChangesAsFeedback` (`POST .../changes/rejected-feedback`, ModelerOnly), all `RunChangesOut`; 409 `changes_unavailable` (with `reason`) or `decisions_closed`, 422 `unknown_change`; logic in `run_changes.py`.
- `routes/run_link.py` — Link an imported version to the Databricks run that produced it: `previewLinkRun` (`POST /businesses/{id}/versions/{version_id}/link-run/preview`, writes nothing) and `linkRun` (`POST .../link-run`, answers `RunOut`), both BusinessAdminOnly; a refusal is `{error: "link_refused", message, problems}`, 409 when the version or the Databricks run is already recorded, else 422; logic in `run_link.py`.
- `routes/run_report.py` — Read-only run report routes (any role): `getRunReport` (`GET /businesses/{id}/runs/{run_id}/report`, `RunReportOut`) and `getVersionReport` (`GET /businesses/{id}/versions/{version_id}/report`, `VersionReportOut` with the producing run's report, a vibe or a unified run's shrink/enlarge step, or null); both assembled by `run_report.build_run_report`, 404 outside the business.
- `routes/versions.py` — Model-version reads (the list derives `is_head` / `draft_state`, `linked_run_id` (`run_link.linked_run_ids`) and `is_imported` (`run_link.import_sources`)), delete through `_version_lifecycle.delete_version`, the business's unfinished `_metamodel` cleanups (`listMetamodelCleanups`) and Retry cleanup (`retryMetamodelCleanup`, under the business lock), per-version artifact endpoints (business-scoped), `getRunDefaults` (the run form's pre-fill for a vibe of the version, `services/run_defaults`), installation drift probe + reconcile over every catalog with an open install row, `importVersionFromVolume` (AdminOnly recovery; optional `databricks_run_id`, linked after the import commits; optional `scope`, settled with `import_model.import_scope`, else the step fails and the route answers 502; the agent's file is not rewritten), `getUninstallImpact` (ModelerOnly; the catalog defaults like the uninstall run's, `resolve_uninstall_target_catalog`, and is lower-cased and checked with `UninstallParams`' pattern, else 422 with a message; optional `cataloging_style`; 429 with `Retry-After` past the per-user scan limit).

one query per table) and `/docs` (Volume docs listing as `DocsOut {folder_url, docs[{path,name,category}]}`, capped, NotFound → empty docs, other errors 409 admin-help incl. `runs_path`, sanitized) and `/docs/content?path=` (run-scoped capped text read via `Dependencies.Client`; 422 bad path, 404 NotFound, 409 admin-help otherwise) for any role, `PUT/DELETE /api/assessment-decisions/{id}/answer` (ModelerOnly; record/clear an answer), `POST /api/assessment-domain-runs/{id}/next-vibes/{next_vibe_id}/feedback` (ModelerOnly; With App creds, `GithubAppTransport` signs an RS256 JWT (pyjwt), mints a 1h installation token (module-level cached, refresh at expires_at-300s or on 401), calls `api.github.com` with `Authorization: Bearer <token>` at 5,000 req/hr (immune to the industry repo's SAML SSO), and routes file reads through the Contents API with `application/vnd.github.raw+json` via the shared `_translate_github_url` rewrite; `capabilities().auth_mode` is `github_app`. No App creds → anonymous (60 req/hr), `auth_mode=anonymous`. The per-user `oauth_u2m` UC connection is NO LONGER selected for reads (EMU/SAML-blocked on the test workspace). Flat repo (industries at root, no sector level) → one synthetic sector; default repo from `agent_config` when set. `fetch_readme` (scope readme, version-readme fallback, `None` on both-missing) + `fetch_releasenotes` (best-effort, `None` on any failure) + module-level `parse_model_statistics` (parses a release-notes "MODEL STATISTICS" block by label, never by line order; all-null on an absent/unparseable block) back the preview's README + domain-statistics fields.
